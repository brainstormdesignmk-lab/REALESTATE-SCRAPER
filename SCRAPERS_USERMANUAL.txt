  PHASE 1: NIGHTLY SCRAPING (22:00)                                                  
                                                                                     
  Step 1: batch_scraper.py Starts                                                    
                                                                                     
  // bash                                                                            
  python3 batch_scraper.py                                                           
                                                                                     
  The script does one thing: finds every  config.json  across all 3 sites, runs      
  the matching base scraper for each.                                                
                                                                                     
  batch_scraper.py                                                                  ▀
    → scans PAZAR3/ for config.json files (finds 9)                                  
    → scans REKLAMA5/ for config.json files (finds 12)                               
    → scans IMOTI247/ for config.json files (finds 8)                                
    → total: 29 categories                                                           
                                                                                     
  It runs them sequentially, one at a time. This is deliberate:                      
  - Only one Chrome instance at a time (Imoti247 needs Chrome, ~200-500MB RAM)       
  - Machine has 7.7GB total, ~150MB free                                             
  - Running even 2 scrapers simultaneously = Chrome crash                            
                                                                                     
  Step 2: Each Scraper Runs                                                          
                                                                                     
  For each of the 29 categories,  batch_scraper.py  calls:                           
                                                                                     
  // bash                                                                            
  python3 PAZAR3/_pazar3_scraper.py PAZAR3/P3_STANOVI_RENTA/config.json              
                                                                                     
  The base scraper:                                                                  
  1. Reads  config.json  → gets URL, category name, pages to scrape                  
  2. Opens its own SQLite DB at  P3_STANOVI_RENTA/data/pazar3.db                     
  3. Loads listing page 1 from the URL                                               
  4. For each ad on the page:                                                        
  - Extracts ad ID from the URL                                         
  - Checks DB: is this ID already there?                                             
  - YES → skip (already scraped before, never re-process)                            
  - NO → continue to scrape this ad                                                  
  5. Loads the individual ad page                                                    
  6. Extracts:                                                                       
  - Title from  <h1>  tag                                                            
  - Phone using site-specific method (see below)                                     
  - Images using site-specific method (see below)                                    
  - Price/Size from title text via regex                                             
  7. Checks: is this an agency ad?                                                   
  - YES → skip (keyword match in title OR phone matches agency blacklist)            
  - NO → save to DB                                                                  
  8. Waits random delay (1.5-3s) → loads next ad                                     
  9. After all ads on page → waits (3-6s) → loads next page                          
  10. Repeats for all pages in config                                               ▄
                                                                                     
  Step 2a: Phone Extraction Per Site                                                 
                                                                                     
  Pazar3:                                                                            
                                                                                     
  // python                                                                          
  # Extracts phones from ad HTML using regex                                         
  # Filters out Pazar3's own number: +389 078 377 677                                
  # Returns: "+389 70 123 456" or "+389 70 123 456 | +389 71 234 567"                
                                                                                     
  Reklama5:                                                                          
                                                                                     
  // python

  # If no phone found, tries "ShowPhone" direct link                                 
  # Filters out known agency phones (САВИЌ: +389 70 318 400)                         
  # Returns: "+389 73 774 725"                                                       
                                                                                     
  Imoti247:                                                                          
                                                                              
  // python                                                                          
  # Calls AJAX endpoint: https://imoti247.com/description.php?get_phone=1&id=AD_ID   
  # Strips dashes/slashes from response (071-810-110 → 071810110)                    
  # Returns: "+389 71 810 110"                                                       
                                                                                     
  Step 2b: Image Extraction Per Site                                                 
                                                                                     
  Pazar3:                                                                            
                                                                                     
  // python                                                                          
  # Selects: img[data-src*='pazar3']                                                 
  # Returns: "https://media.pazar3.mk/Image/UUID/..."                               ▄

  Reklama5:                                                                          
                                                                                     
  // python                                                                          
  # Regex: photos/xbig/[a-f0-9-]+\.jpg                                               
  # Returns: "https://reklama5.mk/photos/xbig/UUID.jpg"                              
  # Typically 3-6 images per ad                                                      
                                                                                     
  Imoti247:                                                                          
                                                                                     
  // python                                                                          
  # Selects: img[src*='imoti247']                                                    
  # Returns: "https://img.imoti247.com/img/0_XXX-800x600.jpeg"                       
  # Typically 5-13 images per ad                                                     
                                                                                     
  Step 2c: What Gets Saved to DB                                                     
                                                                                     
  Each ad creates one row in SQLite:         
  
  // sql                                                                             
  INSERT INTO listings VALUES (                                                      
      id='9006273',                          -- unique ad ID from site               
      title='Banese me qira',                 -- from <h1> tag                       
      price='N/A',                            -- extracted from text (may be N/A)    
      size='N/A',                             -- extracted from text (may be N/A)    
      contact='+389 075 882 840',             -- normalized phone                    
      images='https://media.pazar3.mk/... | https://...',  -- pipe-separated URLs    
      url='https://www.pazar3.mk/oglas/...',  -- full ad page URL                    
      status='',                              -- empty = new, not yet served         
      first_seen='28.08 12:28',               -- when scraped                        
      last_served='',                         -- when last served to Ana             
      times_served=0,                         -- how many times served               
      site='pazar3',                          -- source site                         
      category='Станиви Изнајмување'           -- category name                      
  )                                                                                 ▀
                                                                                     
  Step 2d: Deduplication During Scraping                                             
                                                                                     
  The dedup happens during scraping, not after:         
  
  Day 1: Scraper runs, finds 50 ads                                                  
    → All 50 are NEW (not in DB)                                                     
    → All 50 inserted with status=''                                                 
                                                                                     
  Day 2: Scraper runs again                                                          
    → Finds same 50 ads + 5 new ones                                                 
    → 50 already in DB → SKIP                                                        
    → 5 are NEW → insert with status=''                                              
    → Only 5 new ads processed                                                       
                                                                                     
  Day 15: Scraper runs                                                               
    → Finds 30 ads                                                                   
    → 25 already in DB → SKIP                                                        
    → 5 are NEW → insert                                                            ▄
    → Market pace: 5 new ads today                                                   
                                                                                     
  This means: The scraper never re-processes an ad. It only touches genuinely new    
  listings. This saves time, bandwidth, and avoids duplicates in the DB.

  This script:                                                                       
  1. Finds all 29 DBs:

  - New ads (never served) → included

  Same phone +389 70 123 456 found in:

  Keep the version with most images (best data for Ana)       
  
4. Sorts by priority:                                                              
                                                                                     
  TIER 1 (Apartments):     26 ads  ← TOP OF CSV                                      
  TIER 2 (Commercial/Houses): 45 ads

  WHY THIS DESIGN WORKS                                                              
                                                                                     
  1. No lead is ever lost — everything goes to SQLite, even if CSV generation        
  fails                                                                              
  2. No lead is ever contacted twice — status tracking prevents re-serving           
  contacted leads                                                                    
  3. Fresh leads always come first — priority sorting + status filtering             
  4. One bug fix = one file — base scrapers are shared, not duplicated               
  5. Each category is isolated — one DB crashes, others are fine                     
  6. Disk stays clean — only new ads processed, old ones skipped                     
  7. Ana never sees irrelevant data — dead/contacted/accepted filtered out           
  automatically                                                                      
  8. Carryover works automatically — uncontacted leads sit in DB, served again       
  tomorrow                                                                           
  9. Image fallback exists — if images break,  re_scrape_images(ad_url)  can re-     
  fetch                                                                             
  10. Supabase compatible — CSV can be imported directly

  Why Individual DBs + Combined CSV?                                                 
                                                                                     
  ┌───────────────────┬───────────────────┬───────────────────────────────────┐      
  │ Component         │ Who Uses It       │ Why Separate                      │

  │ (×29)             │ them              │ others fine                       │      
  │ Combined CSV      │ Ana reads it      │ One file to work with, not 29     │      
  │ serve_ana.py      │ Bridge between    │ Reads DBs, writes CSV             │      
  │                   │ the two           │                                   │      
  └───────────────────┴───────────────────┴───────────────────────────────────┘      
                                                                                     
  The DBs are the source of truth. The CSV is a view of that truth, filtered and     
  sorted for Ana's workflow.                                                         
                                                                                     
  Can Ana Pull Directly From Individual DBs?                                         
                                                                                     
  Technically yes — she could open any  data/pazar3.db  in a SQLite browser. But:    
  - She'd need to open 29 separate files                                            ▄
  - No priority sorting                                                              
  - No cross-site deduplication                                                      
  - No status filtering (she'd see contacted/accepted/dead leads too)                
  - She'd need to know which categories to check                                     
                                                                                     
  The combined CSV solves all of this. One file, pre-sorted, pre-filtered, ready     
  to call.
